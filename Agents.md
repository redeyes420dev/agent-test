# 🧠 Архитектура Агентов мультиагентной системы

В данной системе реализованы три специализированных агента, работающих совместно через LangGraph и JSON-RPC. Каждый агент отвечает за ключевой этап в процессе автоматизированной разработки программного обеспечения.

---

## 🧩 Общие принципы

- Все агенты реализованы как **асинхронные воркеры** на Python.
- Взаимодействие между агентами происходит через **LangGraph**, управляемый центральным оркестратором.
- Вызов LLM осуществляется через **OpenAI SDK** (GPT-4.1-mini).
- Логика каждого агента декомпозирована на: `input → planning → action → output → logging`.

---

## 👨‍💻 Agent: Программист

### 📌 Назначение:
Генерация исходного кода на Python / JS / Java / C++ на основе входных требований.

### 🛠️ Механика:
- Использует контекст задачи и целевую платформу
- Делает вызов к LLM с промптом для генерации функций, модулей, классов
- Поддерживает встроенную генерацию докстрингов, аннотаций типов и автоматических примеров

### 🔗 Интерфейс:
```python
class ProgrammingAgent(BaseAgent):
    async def generate_code(self, context: CodeContext) -> str:
        ...
````

### 📂 Пример файлов:

```
agents/
├── programmer.py     # Главная логика генерации кода
├── prompts/
│   └── generate_code.j2  # Jinja-шаблон промпта
```

---

## 🧪 Agent: Тестировщик

### 📌 Назначение:

Генерация unit и integration тестов с использованием `pytest`, `jest` или других подходящих фреймворков.

### 🛠️ Механика:

* Принимает сгенерированный код и контекст требований
* Определяет граничные случаи, валидные/невалидные входы
* Создает покрытие ≥ 80% через `pytest-cov` или `jest --coverage`

### 🔗 Интерфейс:

```python
class TestingAgent(BaseAgent):
    async def generate_tests(self, code: str, language: str) -> List[str]:
        ...
```

### 📂 Пример файлов:

```
agents/
├── tester.py
├── prompts/
│   └── generate_tests.j2
```

---

## 🔍 Agent: Валидатор

### 📌 Назначение:

Проводит статический анализ кода, проверку на уязвимости и соблюдение стиля.

### 🛠️ Механика:

* Использует линтеры: `pylint`, `black`, `eslint`
* Проверяет соответствие OWASP рекомендациям
* Вызывает LLM при необходимости объяснения или автокоррекции ошибок

### 🔗 Интерфейс:

```python
class ValidationAgent(BaseAgent):
    async def validate_code(self, code: str, language: str) -> Dict[str, Any]:
        ...
```

### 📂 Пример файлов:

```
agents/
├── validator.py
├── prompts/
│   └── validate_code.j2
```

---

## 🔄 Взаимодействие агентов

```
[ ProgrammingAgent ] 
        ↓
[ TestingAgent ] 
        ↓
[ ValidationAgent ]
        ↓
[ CI/CD Pipeline ]
```

Оркестрация реализована через `LangGraph` с возможностью перезапуска отдельных этапов.

---

## 🔐 Безопасность

* Агент `Validator` проверяет наличие потенциально опасных конструкций (eval, exec)
* Программист ограничен в доступе к файловой системе — весь код исполняется в `Sandbox`
* Все вызовы логируются и защищаются через audit trail
